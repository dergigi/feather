# Feather

- Native Android: Kotlin, Jetpack Compose, Material 3, Quartz. Reader first: support explicit emoji (kind 7) reactions through the connected signer. Support explicit NWC zaps: 21 sats on tap, a history-based amount picker on long press. Support explicit kind-1 posts and replies with image/video attachments uploaded to the account’s advertised Blossom servers through the connected signer; explicit profile follow/unfollow with fresh NIP-02 list discovery; no DMs. Support minimal public profile search through Vertex NIP-50. Display existing replies, reactions, highlights, and engagement counts.
- Signer-only login (NIP-55, e.g. Amber); no account creation or key import. Request identity signing only for explicit kind-3 profile follow/unfollow changes, kind-10015 hashtag follow/unfollow changes, kind-10063 Blossom server list changes, kind-10000 muted-word and account mute/unmute changes, kind-1 posts, kind-20 picture posts, kind-1/NIP-10 and kind-1111/NIP-22 replies, kind-6/kind-16 reposts, kind-7 emoji reactions, kind-1018 votes on kind-1068 polls, kind-5 deletion requests for the account’s own notes, replies, reactions and reposts, kind-9734 zap requests, kind-1621 public issues for explicit bug reports and feature requests, kind-1984 public account reports for explicit moderation submissions, kind-30078 encrypted Feather preference updates for explicit settings changes, and kind-24242 Blossom upload authorization for explicitly selected images/videos; encrypt/decrypt only the connected account’s own NIP-78 Feather settings and kind-10015 interests and kind-10000 mute lists using NIP-44; also decrypt the connected account’s private mute list and kind-10015 followed-hashtag list (NIP-44 or legacy NIP-04), through its signer. No other private-list access. NWC uses its separate connection secret for encrypted wallet requests; store credentials encrypted with Android Keystore. Never automatically retry an uncertain payment.
- Follow docs/DESIGN.md: icon-only interface chrome, accessible descriptions, content-first typography.
- Convention over configuration: sensible defaults, automatic profile relay sets and discovery, no relay editor or setup wizard. Settings should remain exceptional.
- Keep work off the UI thread unless Android UI APIs require it. Run disk/network I/O, database access, image processing, and substantial parsing on background dispatchers. Bound queues and concurrency; optional cache work must never delay display.
- Keep features, dependencies, relay subscriptions, and caches small and bounded.
- Never explicitly fetch an event ID already held as a complete, verified event in memory or on disk. Use the shared cache-first lookup path, request only missing IDs, and share in-flight requests. New-event discovery and newer replaceable/addressable versions are separate; see docs/DESIGN.md.
- Use standard Android components; system-following light/dark surfaces and Soft Plume blue branding. No theme setting.
- Work directly on master when requested. Use Conventional Commits 1.0.0.
- Write ngit / GRASP issues, comments and resolution summaries on the user's behalf in their first-person voice ("I" or "we" as appropriate), rather than referring to them as "the user" or "the maintainer".
- Route public issue replies through the Feather account: send the Feather agent a NIP-17 DM asking it to reply. Do not post these replies using Gigi's signer.
- Maintain CHANGELOG.md (Keep a Changelog) and Semantic Versioning 2.0.0.
- Increment versionCode for each published APK. Initial development uses 0.x.y.
- Releases include a signed APK on GitHub and a Zapstore publication, following boris-android.
- Never commit credentials, local.properties, .env, or signing keys.
- Use the sole tagline “Nostr with nothing in the way.” The approved promotional line is “Swipe, tap, done.” No other generic supporting slogans; public copy should describe concrete features.
- For kind-1 promotional posts quoting Gigi, keep the quotation and attribution (including the nostr:npub mention and proper p tag) on the same line. Put the blog/article URL on the immediately following line, with no blank line. Keep announcements vertically compact.
- Website is static HTML/CSS on Vercel at feather.dergigi.com. Keep evergreen links to the latest GitHub release and Zapstore, with no app version label. App releases must not update or deploy the website; defer further website work until explicitly requested.
- Prefer fast iteration. Build before publishing. The user tests live on their device through Zapstore; do not run tests or emulators unless explicitly requested. Build only when a release is requested.
- Load media automatically, cache aggressively within the chosen storage budget, and keep feed video playback muted and bounded to three visible players. Prepare neighboring first frames; clips that start playing continue until fully offscreen. Only one clip may be audible.

- Public screenshots (website, Zapstore, release assets) must have Android status bars cropped out before upload. Publish only cropped derivatives; never commit or publish the original status-bar captures.
