# Feather design philosophy

October 10, 2026

Feather is a native Android reader for Nostr. It should feel immediate, quiet, and beautiful: a clean page, a soft blue feather, and room for people’s words. Its small feature set is the foundation of its speed and identity.

## Never fetch an event we already have

A Nostr event is immutable and identified by its content hash. A complete, verified event already on this device satisfies every request for that exact ID. Read it from memory or the persistent event cache; never ask a relay for that ID again while a local copy is retained. This applies throughout Feather, including conversations, quoted notes, reposts, bookmarks, notifications, galleries, and deep links. Navigation, refresh, reconnection, and app restarts are not reasons to re-fetch cached IDs.

Outgoing event references should carry a usable relay hint when known. Prefer persisted relay provenance over an author's advertised outbox: an app listing may live only on a catalog relay. Preserve inherited root hints in replies and hints in shared/copied pointers. Read provenance off the UI thread; never fetch an event again just to construct its reference.

All exact-ID lookups go through one shared, bounded cache-first path. Batch-check the local cache off the UI thread, request only missing IDs, and share in-flight requests between consumers. Remove resolved IDs from the subscription as soon as a verified event arrives, including when it arrives through a different subscription. Clear exact-ID network requests on backgrounding and re-check local copies before resuming. A remembered ID or verification result without the full event is not a cache hit; an evicted event may be fetched again. A cache-read failure must not silently bypass the cache and create a network request.

Discovery is separate: new replies, reactions, zap receipts, deletion requests, and newer replaceable/addressable versions have different event IDs. Continue bounded discovery for those updates without re-requesting known IDs. Broad discovery filters can incidentally return an already-known event; validate/deduplicate it locally. An event in flight when another relay supplies it can still arrive. Do not confuse these deliveries with explicitly requesting a cached ID. Resolving an address such as an article’s `naddr` may discover a newer version; resolving a specific event ID always returns that immutable version.

## Convention over configuration

Feather should work as soon as it opens. Choose sensible shared defaults and use the conventions already attached to a Nostr identity. Every new preference is a cost in attention, interface complexity, and maintenance. Prefer automatic behavior; add a setting only when a meaningful device or accessibility constraint requires it. No setup wizard, relay editor, or technical dashboard belongs in the reading experience.

Connecting a signer supplies identity; its public relay list and follows supply the reading context. Relay discovery, fallback, and connection recovery happen quietly. People should never need to know a relay address to use Feather. The media cache budget is a deliberate exception: device storage is finite, so keep that one useful control, with a sensible 1 GB default.

Account and settings use standard theme-aware bottom sheets, generous spacing, a pale blue accent, and familiar accessible icons. Keep account access on the right of the toolbar. The main toolbar stays outside the horizontal feed pager, with a compact centered selector showing the current category and two neighboring icons on each side, with progressively lower opacity toward the edges. Drive selector icon positions, size, and opacity directly from pager progress so dragging and settling stay in sync. Drag the pill horizontally at one icon width per page, with a bounded flick and page snapping. Preserve tap and long-press actions. Neighbor icons switch pages on tap; clamp the icon window at the ends so Search is the leftmost slot and no empty slots appear; selection moves within the pill near boundaries. Use the same icon vocabulary as profile tabs, without visible labels or a tab underline. Preserve the shared toolbar’s visibility across horizontal swipes and retain vertical hide/show behavior. The main toolbar floats transparently above scrolling feed content; only the five-icon selector has a rounded pill with a semi-transparent theme surface, with theme-aware circular backgrounds behind the feather and account control; keep the first note below it when the feed is at the top. Open the signed-in profile from that avatar. Show the feather logo only on the main feed; omit it whenever a back button is present. Profile views place settings at the top-right and back navigation at the top-left; logout sits at the top of the settings sheet beside the connected identity, accessible without scrolling through a biography. Guests find settings alongside signer login in the account sheet. The account sheet presents identity and only the relevant actions; the profile follows ants-android’s layout with Feather styling: an optional banner below the profile toolbar, avatar beside name and username, a left-aligned biography, and compact icon actions. Show the profile name, truncated to one line, only after the name in the profile header has scrolled out of view. Use a solid theme-aware toolbar. Profile category tabs belong below the full profile information as a sticky list header: pin them to the top of the content viewport while browsing, below the toolbar when it is visible, and return them beneath the profile information when scrolling back. Hide the entire tab row with the toolbar when scrolling down, collapsing its height; reveal both when scrolling up. Drive their offset directly from consumed scroll distance, including flings, rather than a threshold-triggered animation. Keep its surface uncluttered, its spacing generous, and its dividers quiet. Keep biographies compact by default: show at most three lines with an icon-only, accessible expand/collapse chevron when content is hidden. Expanded biographies use the same rich links and Nostr previews as posts, with up to three event cards in place and background reference discovery. Public keys are available through a copy action without occupying the page. Avoid raw protocol values and redundant controls.

## Reading comes first

Use a person-and-key icon for signer login, consistently in the home account control, account sheet and issue reporter. Reserve the door-and-arrow symbol for logout. Keep login icon-only, right-aligned in the account sheet, and accessible as “Log in with an Android signer.”

The main experience is a chronological feed of original notes and NIP-18 text-note reposts. A repost uses a small repost icon and the reposter’s name above the original note, never a visible “reposted by” label. Order it by the repost event’s time; keep the original author, content, media, engagement, and thread actions. Validate enclosed originals independently in the background and fall back to relay discovery when absent. Hide the top bar after 32 dp of downward scrolling and restore it after 32 dp upward; ignore tiny direction changes and restore it at the top. Tap a note’s body or surrounding row to read its conversation. Hand the already-rendered event directly to the detail view and retain it separately from the feed snapshot; never replace a known note with an empty/loading screen while fetching replies. Tap a hashtag to open its chronological feed inside Feather, without introducing a search field. Preserve independent tap actions for links, media, quote previews, and controls; tap its author to read their profile. Preserve the reader’s position when they leave and return. Show cached content promptly, then reconcile relay updates without interrupting reading.

Feather does not create accounts, import keys, edit follows, or support DMs. There are no recommendations or analytics. Tapping a post’s heart sends 🧡 through the connected Android signer; long-press offers six recent/frequent emoji choices plus a full-picker icon. Tapping the displayed reaction again removes it with a signed kind-5 deletion request; selected picker emojis toggle off the same way. Existing public activity is readable: profile tabs separate posts, replies, reactions, and highlights; posts display discovered reply and reaction counts and total validated zap amounts in sats. Counts must not delay rendering. Fetch provider metadata and validate zap receipts on a bounded background worker, then update counts. Never imply an exhaustive network-wide total. Feature proposals must justify the attention, network traffic, memory, and maintenance they add.

Profile tabs use accessible icons without text labels and appear only for discovered public activity. Hide empty categories, including Highlights; probe each supported kind independently in the background so busy note feeds cannot crowd out rarer content. Keep discovered tabs stable while viewing a profile, and make swipes skip hidden tabs. Tap tabs or swipe horizontally between adjacent tabs, without wrapping at the ends. Require a deliberate horizontal gesture so vertical scrolling and refresh keep their behavior. Switching tabs preserves the current list position and toolbar visibility. Neither tapping nor swiping a tab should force a jump to the header or tab bar. Highlights follow ants-android’s reading treatment: surrounding context, warm yellow emphasis on the selected passage, an optional comment above a quiet divider, and linked source/author attribution. Markdown formatting and passage matching run off the UI thread. Detail views show full text and media; feed previews stay compact.

## Content supplies the words

Use familiar icons instead of visible labels wherever an icon can express the action. Load older notes automatically within six items of the list end, using a quiet footer progress indicator and no load-more control. Keep one history request active, read cached pages first, retain visible anchors in bounded windows, and avoid repeatedly requesting an unchanged boundary. Pull-to-refresh returns to the latest notes. Refresh by pulling down on the reading list; expose the same action to screen readers without a visible button. Navigation, account access, settings, expansion, conversation, sharing, and confirmation should not introduce interface prose. Avoid screen titles, empty-state slogans and explanatory paragraphs inside the app. The exception is brief, dismissible first-use hints for login and swipe navigation; remember dismissals locally. A skippable first-launch-only welcome carries the system splash feather into a gentle downward drift, reveals login at its normal position and waits for dismissal of a “Connect your signer to log in” hint followed by the swipe hint and live feed switcher on the welcome surface. Swiping previews different colored feathers without ending the welcome; dismiss the swipe hint to drop the selected feather, then fade the background into the selected feed into the feed loading underneath. Match system light/dark surfaces, respect disabled animations, and bypass the welcome for shared media and deep links. Hide compose floating action buttons while logged out.

The text people came to read remains: notes, names, biographies, timestamps, public keys, and link destinations. Media storage amounts are values, not labels. A concise error may explain a failure when an icon cannot tell someone how to recover. Android’s signer chooser and system dialogs retain their platform UI.

Every actionable icon needs an accurate accessibility description and a touch target of at least 48 dp. Support TalkBack, large text, and Android navigation. Never make color the only way to identify an action or state. If a feature cannot be understood with familiar controls, simplify its interaction before adding it.

## Lightness is visible

Use the Soft Plume feather, white backgrounds, pale blue surfaces, sky-blue accents, and dark readable text in light mode. Follow Android’s system dark-mode setting automatically: deep blue-charcoal surfaces, soft light text, and the same feather-blue accents. No theme configuration. Use semantic theme colors for controls, links, placeholders, dividers, sheets, and launch surfaces. Keep the decorative blue gentle; use the darker action blue where contrast matters. Favor space, alignment, and typography over borders, cards, shadows, and decoration.

Use Android typography and standard Material components. Set comfortable line spacing for notes, keep author details secondary, and separate feed/profile notes and conversation branches with spacing rather than horizontal divider lines. Vertical avatar connectors show which replies belong together. Avoid remote fonts and heavy animations. A feed should feel like reading a page rather than operating a dashboard.

## References belong in the conversation

Render Nostr profile mentions as tappable names and quoted text notes as quiet pale-blue previews. Keep ordinary text selectable. Use Quartz to decode NIP-19 identifiers, follow relay hints within the shared connection budget, and verify fetched events before display. Display cached content first. Preview at most three quotes per note and one nesting level; deeper references stay links. Unsupported event kinds open externally. Missing notes retain an unobtrusive reference that can be opened.

Resolve metadata for visible notes and a few upcoming items, including quote authors and profile mentions. Bound requests to 160 profile identities and 24 quoted notes at once; include a metadata indexer within the existing twelve-route budget. Keep metadata requests alive through routing changes. Cache parsed reference lists so scrolling and relay updates do not repeatedly decode the same identifiers.

## Conversations follow real reply edges

Detail toolbars offer copy, share and a phone-shaped open-in-app action. The latter opens Android's chooser for the current note's `nostr:` reference, excluding Feather even when it is the default handler. Use `nevent` with author/kind for ordinary events and `naddr` for addressable content such as articles and app listings. Resolve compatible apps off-main using narrow intent visibility; show a brief copyable message if none is installed. Keep the existing conversation and reading position when returning.

Render the actual root post at normal feed width, including its media and actions, even when a reply is selected. Identify roots by the absence of a reply parent, not by their position in the currently loaded rows. A missing, hidden or deleted parent does not turn a reply into a root. Keep the root's connector out of its full-width content: start it at the lower-left tip of the root's reply icon, connecting to the next reply's avatar. Pin that tip to the avatar axis; keep the icon in a fixed slot with counts growing to its right, and mirror the geometry in right-to-left layouts. Continue using the avatar gutter for surrounding replies and any continuation control.

Opening a note keeps that note as the focus: show its ancestor chain above it and separate reply branches below it. Use quiet vertical connectors between avatars, compact surrounding replies, and larger full-width text/media for the selected note. Do not indent repeatedly at every depth; deep conversations must remain readable on a phone. Keep the selected note’s single-line parent preview while its immediate parent is unresolved. Replace its leading icon with a small muted spinner while resolving earlier context; observe existing requests and stop on completion or a bounded timeout, without extra relay requests. Once that parent is rendered above the selected note, fade and collapse the redundant summary in place. Cached ancestors need no initial summary flash; a missing, hidden or deleted gap does not count as a rendered parent. Keep the existing reading anchor as the summary contracts. Keep the existing profile, timestamp, media, reply, repost, reaction and zap interactions.

Use one parent resolver for rendering, reply classification and counts. For NIP-10, prefer an explicit `reply` marker, then a lone `root`; for old positional tags, use the last unmarked `e` as the immediate parent and the first as the root. Exclude marked mentions and explicit quotes. For NIP-22 comments and voice replies, lowercase tags identify the immediate parent and uppercase tags identify the root scope. Prefer an address when a comment supplies both an address and a particular version of that addressable event. Preserve the existing legacy Zapstore uppercase-only app-comment convention. Quotes are separate previews, never conversation edges. An ancestor is not necessarily a direct parent, and sharing a root does not make two replies siblings.

Order direct reply branches with the selected author's continuations first, then by time and event ID. Preview up to three notes along an ordinary branch, or up to 24 consecutive posts from the selected author. Three vertical dots continue the avatar rail when a preview has more branches, using the rail’s color. Place them in the avatar gutter alongside the note actions rather than in a separate row. Give them a full touch target that does not overlap the reply control; in a conversation they expand the branch in place, using cached events first and the existing bounded discovery path. Retain up to 64 explicit expansions per visit. Feed previews still open the conversation. The Posts feed/profile can show a connected self-thread preview of up to three notes using already available events; it must not start a crawl across the whole feed. Keep feed anchors in chronological order and render each event once per projection.

Resolve ancestors from verified memory/disk copies before asking relays. All missing exact IDs use the shared lookup path: one selected event, up to eight missing parents and 24 visible embedded references. Bound each conversation to 320 retained candidate events, initially 31 ancestors above the selected note, and discovery of children for at most 12 parent IDs at a time. The upper ellipsis extends ancestry in place: reveal up to 32 additional ancestors per explicit tap, up to 255 total, without changing the focused note or adding a navigation entry. Retain that depth for the visit and across Android recreation. A missing-parent tap checks the cache before explicitly retrying an exhausted lookup through the shared subscription; a request already in progress is shared. Keep one parent-expansion job and prioritize the tapped gap within the existing eight-parent lookup budget. Show a small spinner in that gap while loading, with a bounded timeout. Preserve the visible note’s offset when the old gap is replaced by earlier notes. Query NIP-10 root references and NIP-22 root/address scopes separately from immediate-parent joins. Use visible branch parents plus a small initial preview for further discovery; reuse the existing relay budget and author/hint routing. Graph construction and cache joins run off-main. This is a bounded view of discovered replies, not a promise of exhaustive network-wide history.

Missing, sensitive, deleted and cyclic ancestry must not produce invented links or silently join unrelated branches. Stop at that boundary, use a distinct accessible gap control, and load supported missing/earlier references into the current thread when their ellipsis is tapped. Honor deletion requests only after verifying the event and matching the original author's key; address deletions apply only through their timestamp. Retain a bounded set of verified deleted-note IDs so navigating back cannot resurrect the same note from an older UI snapshot. Unsupported parent kinds keep an external link.

Deleted notes in conversations stay collapsed behind a trash icon. If an unexpired copy is already cached and passes the current mute/sensitive-content rules, show an eye toggle beside it. Reveal selectable cached text inline with a muted deleted label, and collapse it on a second tap. Keep the placeholder's event key stable, preserve known reply connections, and animate the height change. This read-only preview has no reply/repost/reaction/zap controls, link navigation or automatic media loading. Do not fetch known-deleted IDs to recover content, create an archive, or extend normal cache retention for this feature. Without a cached copy, show only the deletion placeholder.

Restore cached conversations through a separate background path so feed, profile metadata and engagement snapshots cannot delay or overwrite their graph. Persist only membership IDs for the eight most recently opened threads: up to 320 candidate notes and 256 deletion requests each. Keep signed events in the existing SQLite store; protect these members from publication-age pruning, including at startup. Existing per-kind limits still apply to unprotected events, and expiry remains authoritative. A shared memory cache holds at most 512 recent thread events or an estimated 4 MiB. Coalesce atomic membership writes outside the display path. Rebuild relationships from the signed tags, apply current mute/content/deletion rules, and reject stale results after navigation or account changes. New-reply discovery runs independently; reopening never needs a relay response merely to rediscover already cached relationships. This bounded recent history does not promise permanent storage of every thread.

Stable event keys preserve the reading anchor as earlier notes arrive. Apply initial/restored scroll requests to the current projection before measurement, never through a delayed index-based scroll. Short conversations reserve only the remaining viewport height below the entry anchor so end-of-list clamping cannot pull ancestors into view. Measure this space in the same layout pass as note heights. Once the reader scrolls, retain their visible item/offset rather than repeatedly scrolling back to the selected note. Each navigation entry keeps its graph and scroll state; reopening a branch never resets its parent screen. Save the visible note key/offset for Android recreation, fall back to the selected note if that anchor is no longer available, and never replace a known selected note with a whole-page loading state. Pull-to-refresh discovers new replies and deletion requests without refetching cached event IDs.

References: [NIP-10](https://github.com/nostr-protocol/nips/blob/master/10.md), [NIP-22](https://github.com/nostr-protocol/nips/blob/master/22.md), and [Twitter's grouped conversation design](https://blog.x.com/en_us/a/2015/making-conversations-easier-to-follow-on-the-tweet-page). Adapt the grouping and visual continuity to Feather's minimal controls and Nostr's signed event graph.

Rollback checkpoint: `checkpoint/cache-first-before-threads` preserves 0.58.1, including the cache-first lookup fix, before this redesign.

## Native and economical

Build with Kotlin, Jetpack Compose, Material 3, and Quartz. Use Coil for images and Android Media3 for video. Reuse platform controls and protocol implementations. Do not build a custom UI renderer or drawing framework.

Render lists lazily with stable event identifiers. Keep work off the main thread unless Android UI APIs require it. Disk and network I/O, image processing, substantial parsing, signature verification, and database queries belong on background dispatchers. Keep UI work limited to input, state presentation, layout, and rendering. Bound background concurrency as carefully as memory; optional cache work must never delay visible content. Bound event caches, subscription filters, in-memory snapshots, and relay connections. Coalesce updates without indefinitely delaying visible content under continuous relay traffic. Pause networking when the app is in the background.

Performance claims need measurements from release builds on real devices. Track cold launch to cached content, scrolling frame times, memory, APK size, and network use. Treat emulator observations as smoke tests, not proof of device performance. Prefer removing work over adding elaborate machinery to hide its cost.

## Media appears automatically

Load profile pictures and inline images automatically. Reuse a shared image loader, decode to display size, and prefetch avatars, images, and video posters for six notes ahead and two behind. Keep at most two speculative requests active with their own HTTP scheduling so they do not occupy visible-image request slots. Share memory and disk caches between both paths, preserve useful downloads across scrolling, and re-evaluate when metadata arrives. Plan URLs off the UI thread and cancel obsolete work or all prefetch work when backgrounded. Use full-width inline images at their natural aspect ratio, without cropping or side bars. Ordinary notes render up to 32 media attachments, including in detail views; keep compact embedded previews bounded separately. Reserve space from published dimensions or a bounded cache of prefetched image dimensions; when neither is known, correct the temporary placeholder ratio as soon as decoding supplies it. Show initials while an avatar is unavailable. Tap an image to open the full-screen gallery, never as a prerequisite for loading it. Reuse the gallery behavior from ants-android and boris-android: swiping, pinch/double-tap zoom, background switching, and image save/share actions. Keep profile search in its dedicated main-feed page. Gallery images fit the full viewport in either orientation, preserving their aspect ratio without reserving toolbar/footer space. Hide status/navigation bars with transient system-swipe access. Floating icon controls start hidden; single tap toggles them, swiping/zooming hides them, and three seconds of inactivity fades them away (respecting accessibility timeouts). Keep controls visible during menus or save/share work. Retain the numeric page counter only for multiple images. Profile avatars and banners share a dedicated gallery, ordered avatar then banner and opened at the tapped image; omit missing images and never expand this pair into the profile’s Photos album. Gallery overlays present 21-sat zap, reaction, and open-note actions, in that order from top to bottom, as separate 56dp circular floating buttons at the lower right. Dim gallery zaps without a connected wallet; tapping opens NWC setup and returns to the same image on dismissal, without queuing a payment. Dim both zap and reaction while logged out; tapping either opens signer login. Reuse the post action logic for the selected image’s source event, including long-press emoji and zap amount selection and reaction removal; omit counts inside these icon-only buttons. Hide these actions for images without a known source note. Pause control hiding while a picker or payment/reaction is pending, and scope engagement loading to the selected source.

Autoplay a visible video, muted by default. Keep one player and decoder active across the reading screen; initially choose the video nearest its center. Retain the current video while any part remains visible, including videos taller than the viewport. Switch only after it leaves the viewport; stop background playback. Reuse standard Android media controls and provide an accessible sound toggle.

Cache aggressively on the device. Let the reader choose a total media-storage budget in settings: 128 MB, 256 MB, 512 MB, 1 GB, or 2 GB; default to 1 GB. Reserve one quarter for images and three quarters for video, with least-recently-used eviction. Bound decoded-image memory separately. Reuse cached media across launches; Android may reclaim these cache files when storage is needed.

Avoid adding a media proxy or backend to this release. Direct loading keeps the implementation small, although first loads still download the source image. Avatars at unchanged URLs use weekly cache keys so they can eventually refresh. After loading an avatar, create a 256-pixel square WebP thumbnail on the device. Reuse that derivative for small avatars, sharing the image LRU and budget with separately cached originals. Return decoded avatars for display immediately; generate thumbnails afterward on one background worker with at most four queued writes. Deduplicate pending work and skip optional writes when full. Stop the worker before replacing its cache. Decode and encode off the UI thread; retry transient image failures twice while active. No image-processing server is needed. Video caches fill as playback buffers; the disk budget does not promise a complete offline copy of every clip.

## Identity belongs to the signer

Account access uses an Android NIP-55 signer such as Amber, exclusively. Login requests only the public identity. An explicit heart tap or picker selection requests signing of a kind-7 emoji reaction; a bolt tap requests a kind-9734 zap request and a 21-sat NWC payment; decryption requests are limited to the connected account’s private mute list, kind-10015 followed-hashtag list, and its own NIP-78 Feather preferences, through its signer. The separate wallet connection key encrypts NWC requests; identity-key encryption is requested only for explicit Feather preference updates (NIP-44 to self). Account creation and private-key management belong in the signer. A disconnected public feed is browsing, not an alternative login method.

Existing follows come from the account’s public contact list. Feather never changes those follows. Publishing is limited to explicit emoji reactions and zap requests.

## Relays are automatic

Use the account’s signed [NIP-65 relay list](https://github.com/nostr-protocol/nips/blob/master/65.md) automatically. Prioritize its read and write relays, discover followed authors’ write relays, and use a conversation author’s read relays to help find replies. Verify events before using them, respect replaceable-event ordering, and cache relay lists across launches. There is no relay configuration UI; old manual preferences are discarded.

Keep twelve built-in seed candidates for bootstrap and fallback, selecting up to four base routes at a time. Once the account’s list is available, its relays take priority in the base routes, retaining a seed for discovery. A shared pool adds up to eight routes for the account, current reading context, and authors covered by common outboxes. Route each author's notes through up to two advertised write relays, with automatic fallback when none is usable. Guests also discover relay lists for a bounded sample of visible-feed authors.

Reconcile discovery quietly while the app is in the foreground. Failed or refused connections receive a two-minute cooldown; choose another candidate without exposing a relay error or asking the reader to fix anything. Rotate seed batches every thirty seconds when no connection is available or an account's relay list is still missing. Keep healthy guest routes stable. Existing WebSocket heartbeats detect broken connections. Cancel discovery work when the app goes to the background. This is opportunistic recovery, not a guarantee that every relay is live or every note retrievable. Authenticated relays remain outside the reader's scope.

[NIP-66](https://github.com/nostr-protocol/nips/blob/master/66.md) monitor reports may eventually supplement local connection evidence. They are not implemented yet. Before adding them, define trusted independent monitors, freshness limits, and a bounded query budget. Never depend on monitoring data to connect, and never let one monitor silently remove an account's relay set. Lightweight discovery should serve reading, not turn Feather into a relay crawler.

## Review every addition

Before shipping, check the feed on a small screen and with enlarged text. Check icon semantics, touch targets, long notes, empty feeds, failed connections, and cached reading. Verify that leaving the app stops network work and that opening a profile or conversation does not lose the feed position.

A change belongs in Feather when it makes reading simpler, faster, or more beautiful without expanding the product beyond its purpose.


## Video interaction

Video system artwork prefers the advertised thumbnail, then a frame copied from the already-decoded playback surface, then the author’s avatar. A theme-aware Feather image fills any remaining gap. Capture bounded 512px frames without downloading or decoding a second video; encode off the UI thread and cache derivatives in the existing image LRU. Artwork failure must not affect playback.

Fullscreen and audible videos expose the existing player through a Media3 session service, without a second decoder or a timeline reset. Keep only the selected clip active when the app backgrounds or the screen locks; stop it when its reader destination is removed. Muted inline autoplay previews do not create notifications. Audio and video sessions hand off playback so only one is audible. System controls provide play/pause, ±10-second seeking, speed cycling through 3x, the Feather icon, and a source-note intent. Release the session before releasing its clip. Speed icons use real font outlines with one size, weight, and baseline across all values.

Retain the last playback position and volume for up to 64 video URLs in process memory. Restore sound only when the clip starts, keeping prepared neighbors silent and using the existing single-audible-clip policy. Save when a watched player is deactivated or released and restore before preparing its replacement, so moving between feed and note detail preserves progress. Prepared, unwatched neighbors must not overwrite resume points; live streams keep their default live position.

Keep feed autoplay muted and bounded to three visible players. Prepare neighboring visible clips paused so their first frame is displayed, then start the clip nearest the viewport center once scrolling settles briefly. Once started, keep it playing while any part remains visible; release it only when completely offscreen. Respect manual pauses. Retain existing playing edge clips before assigning remaining slots, and keep at most one player audible. Pause and release decoder/loading activity when backgrounded or covered, preserving position for return. Fullscreen pins its clip and suspends the others. Expose fullscreen and mute icons; double-tap left/right to seek ten seconds without opening the note. Vertical feed gestures continue scrolling the list. Fullscreen reuses the same player and cache, preserving the timeline, pause state, speed, and mute state across view transitions and rotation. Pause in the background and restore intentional playback on return; muted autoplay must not take audio focus from another app.

Use Media3’s native, auto-hiding timeline, play/pause, seek, playback-speed, and available subtitle controls. In fullscreen, horizontal swipes preview a seek and commit on release; left-side vertical swipes adjust this window’s brightness and right-side vertical swipes explicitly unmute playback and adjust Android’s media volume. Start from the current device volume, update only when its discrete step changes, and report the actual resulting level. Give brief icon-and-value feedback. Keep native controls accessible independently of gestures.

The fullscreen toolbar offers download, file sharing, and copy URL alongside mute and close. File exports reuse cached ranges, stream missing bytes on IO, and serialize exports without blocking playback. Store saved videos in Movies; temporary share files are retained for receiving apps, cleaned after a day on the next export, and bounded to the smaller of the selected media budget or 512 MiB. Closing fullscreen cancels an unfinished export and removes partial output. No new settings or player dependency.


## Blocktime

Default timestamps to compact relative age (`5h`, `2d`, `1w`). Tapping any timestamp cycles the app-wide format from relative age to date/time to comma-separated Bitcoin block height (`987,654`), then back to relative age. Persist this choice on IO across app restarts; new notes and all screens share it. Relative labels update at their next unit boundary only while visible and foregrounded. Resolve only requested timestamps through mempool.space’s block timestamp endpoint; retain the date while loading and when unavailable. This maps the note time to a block timestamp at or before it, not a cryptographic proof of publication time. Use one lookup at a time and a 512-entry memory cache backed by a permanent timestamp-to-height SQLite table in app data. Persist successful results on IO before displaying them, with no expiry or pruning; repeated timestamps read the stored result even after restart or memory eviction. Migrate valid legacy JSON entries, including expired ones. Failed lookups have a short retry cooldown and are not stored permanently. Cancel foreground lookups when backgrounded. No new settings or offscreen block-height prefetch.

## Loading and link previews

Reserve the feather for identity, never a loading or empty-state indicator. Show a small native spinner for pending content, including background preparation and brief cache/relay handoffs. Leave settled empty feeds quiet; retain tappable diagnostics for errors, unavailable posts, and hidden content. The system launch screen uses a transparent feather drawable on the current light/dark surface.

Animate GIFs with Coil's native image decoders. Stop animation outside the visible window, behind fullscreen media, and when backgrounded. Keep image downloads and decoding in the existing bounded cache pipeline.

YouTube links show lightweight cards: thumbnail, title, and channel attribution. Render the thumbnail immediately, then fetch oEmbed metadata in the background only for visible cards.
